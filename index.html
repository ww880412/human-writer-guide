从题目到定稿，关键选择由你回答。

  1. 选题 → 框架得到 brief.md 和 outline.md。你确认框架后，才开始写正文。
  2. 写稿 → 自查得到 draft.md 与问题报告。缺资料先标待补；有意见时修改一次，修改者自检。
  3. 修改 → 交稿按报告改一次，交代未完成项；不自动再审或弹定稿卡。
  4. 作者决定 → 定稿说“定稿”才开卡；“只定稿”固定版本；“继续修改”回润色；“补充内容”回写稿。

导入稿件从自查开始。自查无意见时直接询问定稿；冲突候选未处理时，不能推进或定稿。定稿后可接 Word 与演示；公众号排版和自动发布尚未开放。

补内容回写稿，只改措辞才走润色。

  1. 先写清要求requirements.md 记录适用标准 S、保持项 K、本轮目标 G；材料留在 materials/。
  2. 确认修改范围直接说要怎么改，在卡上选择内容修改或只改措辞。写下目标本身不触发修改。
  3. 修订留下依据写稿修订交付新正文和 changes.md，记录改了哪里、依据是什么，以及保持项冲突。
  4. 修改后交稿修改者自检并交代未完成项；需要再审时，由你主动发起。

要按新思路重组整篇，先把主线写入保持项，再 go outline；确认框架后按框架重组，并逐节说明原内容的去向。写稿和润色都遵守冻结的写作要求。

流程不变，写作方法可以换。

  1. 本次指定“这次用 dbs-ai-check 自查”只影响本次执行。
  2. 作品绑定“这篇以后的自查都用 dbs-ai-check”保存为本作品的自查选择。
  3. 独立对比用同一基准和要求生成另一份候选，由你决定是否采用；主线阶段不变。
  4. 先查可用目录本次指定优先于作品绑定，其后是工作区默认、内置默认。只使用目录中可用的组合；样本验收与真实使用效果分开查看。

我自己编辑，模型也在改，怎么办？

检测到冲突时，优先保留作者正文，模型产物转为候选。你可以采用候选、保留当前稿，或手工处理。冲突未处理前，流程不会推进或定稿。

在 Word 里改过，怎样接回来？

成品里的改动不会自动回写 Markdown。要改正文，明确授权将 DOCX 转回文本并核对转换损失；正文修改后重新定稿，再更新成品。只改成品呈现可直接说明，例如“第 2 页要点减成两条”。

它会自动学会我的文风吗？

当前只传递作者偏好文件，供写稿与润色使用，不会自动学习文风。需要你提供偏好或样本，并实际检查产物。

编辑器若持有已移走文件的句柄，修改可能留在恢复目录；极短的检查与改名之间仍有竞态窗口。版本保护不等于完整备份。文件保护和验证边界 →
