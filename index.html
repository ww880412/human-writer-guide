一份材料的写作过程 作者参与
  1. 说清题目，放入素材 先确定读者、目的与已有事实
  2. 先看框架，再开始写 确认框架，或重新梳理
  3. 写稿、自查、按意见润色 缺失信息标为待补，由你选择采纳意见
  4. 只定稿，还是再补一点 继续修改或补充内容，保留版本记录

已有稿件可从自查开始。关卡等你回答，沉默不算同意。

02 / IMPORT

已经写好一篇稿件

从自查开始，自己决定哪些意见要改，再看润色结果。导入文件作为只读来源保留。

$human-writer import source.md
  1. 将稿件放在当前项目目录中。
  2. 导入后，在 works/<slug>/draft.md 继续。
  3. 选择采纳意见、继续修改或只定稿。

你与 agent 的分工

自动走步骤，关键处停下来。

过程 agent 做什么 你决定什么
选题与框架 整理读者、目的、材料和章节结构 框架确认后才进入写稿
正文与自查 按素材写稿；把问题列成报告 全部采纳、只改表达、只改高严重度，或输入编号
润色与复查 按选中的意见改稿；每轮至多自动复查一次 继续修改、补充内容，或只定稿
遇到冲突 保留作者内容，给出候选稿或新产物文件 采用候选、保留当前稿，或手工处理

报告不保证事实正确；重要事实仍须你核对。查看文件保护和验证边界。

可替换的方法

换写法，沿用同一套流程。

流程负责作品和关卡，技能负责怎么写。一次指定或绑定到当前作品都可以。

选题、框架、写稿 试用

默认使用 material-brief、material-outline、material-draft；框架也可用 pyramid-long-form，写稿也可用 md-report-summary。

试用表示通过结构检查、已有样本运行，但真实材料的写作效果仍需持续观察。

自查与润色

dbs-ai-check 提供自查方法，humanizer-zh 负责中文润色。插件保存采纳决定和版本，技能不会全局安装。

dbs-ai-check 使用 CC BY-NC 4.0，含非商业使用限制。各组件许可分别适用。
