02 · 路线如何推进

题目 → 选题 → 框架 → 作者确认 → 写稿

导入稿件 / 写稿完成 → 自查

有问题 → 采纳意见 → 润色 → 复查至多一次

无问题 / 复查完成 → 定稿卡

  • 只定稿 → 完成。
  • 继续修改 → 等待作者要求 → 润色。
  • 补充内容 → 等待作者要求 → 写稿。

加粗的关卡需要作者在原生卡片作答。流程允许作者跳转，但 agent 不代替作者回答，不把聊天表态伪造为关卡回执。

Codex 插件缓存 运行时、技能、适配与锁定 SDK；更新时校验包内容

两个 hook 分别承接会话开始和作者消息。MCP 不用自己的缓存目录猜项目；它从会话绑定中取得项目。

04 · 保护到哪里，边界在哪里

并发保存

写入前先移开工作文件，再核对移开的内容。检测到作者变更时优先保留作者文件；正文产物进入候选处理，选题 / 框架产物保存为 .new.md。崩溃恢复沿同一判断重放。

编辑器持有旧文件描述符写入时，新内容可能落在移开文件中，需按保留路径找回。检查目标不存在与随后改名之间仍有一个极窄的竞争窗口。这里不承诺绝对无丢失，也不能代替备份。

事实与质量

检查器能验证结构、素材引用、格式和编号，不能自动证明所有事实真实、所有观点合理。模型可能少读材料、误解数据或给出多余待补；重要事实由作者复核。

宿主与界面

CLI 隔离宿主已运行，Desktop 自由输入编号已有证据。菜单入口插入格式、Desktop 重启与特定编辑器重载的完整表现仍需实际使用观察；卡片折叠可要求 resume。
