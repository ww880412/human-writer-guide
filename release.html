默认 · 在 Codex 内完成

这一步，交给子 agent

框架、写稿、自查、润色及成品环节，默认交给不继承主会话对话的子 agent。它按本次任务与冻结输入产出，主会话负责提交和向你呈现结果。

$human-writer

无需额外切换模式。选题和无作品的单次使用仍由主会话完成；宿主派不出子 agent 时会说明并回退。

按需 · 交给别的模型或工具

想用 Claude Code 或 Devin 做这一步，直接告诉主会话交给谁。交接包包含任务说明、冻结输入和素材副本，对方不需要安装 Human Writer。

0.3.2 · 路线、自查与反馈

你要做的事这版的变化
看清当前进度输入 $human-writer 或 $human-writer status，查看路线、每步技能、当前位置和下一步；定稿后也显示 Word 与演示各自的进度。
知道从哪开始入口列出六种用法：从题目写、改已有稿、按新思路重组、做 Word 或演示、看看写法、记个反馈。
说清成品哪里不好成品自查增加“取舍”“设计”“渲染”三层意见；涉及选图、删减或页面主线的问题标明“需改方案”。已有内容失真检查继续保留。
区分成品问题与检查限制检查环境打不开或无法渲染时，单独给出低严重度的“未能渲染”说明，写明未检查范围，不据此断言作者环境有缺字或版面缺陷。
留下使用反馈说“记个反馈：……”后，模型在项目根目录追加反馈文件，记录原话和定位信息，不抄正文、素材或成品文字与数字；累计五条未交出的反馈时提醒交给维护者。

成品自查继续开放试用。具体意见仍需作者判断，不能把“检查过”当成所有版面问题都已发现。

同时带入 0.3.1 的三项修复

  • 答卡更稳：识别答复标签外的首尾空白，重复收取同一答复仍只推进一次。
  • 修订后继续查论证：补查案例是否可比、团队判断与个人归因是否混淆、措施是否对应问题。
  • 有来源的轴刻度可用：允许契约约定的水平、零起点、等距 SVG 线性轴刻度；业务数字仍需有来源，竖直数值轴不在本次支持范围。
